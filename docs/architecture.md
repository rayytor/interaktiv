# Architecture

Rayyan Ekitap is a GTK 4 / libadwaita application written in Python. It reads PDF
textbooks with PyMuPDF and draws, on top of each page, the activity regions
that were computed ahead of time by the hotspot pipeline
([hotspot-pipeline.md](hotspot-pipeline.md)). Nothing is detected at run time.

## Layout of the repository

```
interaktiv_core/        No user interface. Imported by the app and by the pipeline.
  catalogue.py          The book catalogue, installed books, downloads (BooksManager).
  regions.py            The bake format: activity regions per page (regions.json).
  oges.py, linking.py   The publisher's interactive index and how it joins the regions.
  geometry.py           PDF user space <-> widget pixels.
  jobs.py               Background work: bake on arrival, fetch activities, trim memory.
interaktiv_gtk/         The application.
  app.py, window.py     Adw.Application; one window holding a page stack.
  library/              The catalogue view: cards, the "continue" shelf, downloads.
  reader/               The book view: spread and scroll canvases, dock, sidebar, search, focus mode.
  render/               The renderer process, its protocol, the request queue, the texture cache.
  widgets/              Small widgets that libadwaita 1.2 lacks (segmented control, number pad, ...).
  theme.py, style.css   The four themes' palettes and the stylesheet.
  icons/, fonts/        The app's own icon set (generated by tools/make_icons.py) and Inter.
  board.py, failure.py  Pardus ETAP integration; how a failure to start is reported.
packaging/board/        The USB-stick bundle for boards (see packaging.md).
tools/                  Development tools and the hotspot pipeline.
tests/                  pytest; runs under Xvfb.
```

Data next to the code: `kitap_pdf_linkleri.txt` (the catalogue: titles and
CDN links), `thumbnails/` (covers), `activities_meta/` (the publisher's
interactive index per book), `activities/books/<id>/regions.json` (the bakes),
`books/` (installed PDFs, not committed).

## The reader

**Rendering.** PyMuPDF does not release the GIL while it renders, so the
renderer is a child process (`render/worker.py`) talking a small length-prefixed
protocol over pipes. `render/service.py` keeps the queue in front of it: work is
keyed by (page, scale, rotation, clip) so that a held page-turn button never
queues twenty renders; a generation counter drops requests that a page turn or
zoom has made stale; and lanes keep a visible page ahead of a prefetch, a
prefetch ahead of a thumbnail. Results come back as `Gdk.Texture`s into an
LRU `TextureCache` with a byte budget.

**Two canvases.** `reader/spread.py` lays out one or two pages by hand in
`do_size_allocate`, the only place a fit-to-page scale is known. `reader/scroll_mode.py`
is a `Gtk.ListView` of pages; because a list view keeps about two hundred rows
bound whatever the viewport, pages are rendered only while their row is near
the screen and give their texture back when it leaves.

**Pages.** `reader/page_view.py` draws one page: the texture, the search
highlights and the activity marks, all in one snapshot. Hit testing goes
through `interaktiv_core.linking.hit_test`, the same code that placed the
marks, so what is drawn and what can be pressed cannot drift apart.

**Focus mode** (`reader/focus.py`) asks the renderer for a clip of the page at
a scale that fills the stage, and shows the same part of the already-rendered
page until the sharp crop arrives.

**Touch.** `touch.py` holds the rules a finger needs: a tap is decided on
release, not press; a swipe is recognised in an ancestor's capture phase before
the scrolled window claims the drag; long press shows the name of an icon
button, since GTK never shows tooltips to a touchscreen. `board.py` holds off
ETAP's long-press-to-right-click daemon while the window is active.

## Compatibility floor

The oldest board runs Debian 12: Python 3.11, GTK 4.8, libadwaita 1.2. The
code uses nothing newer; `tools/check_api_floor.py` checks the source against
the GIR files, and `packaging/board/test-floor.sh` runs the test suite and the
screenshot tool inside a Debian 12 container. The widgets that libadwaita 1.2
does not have -- a page stack, a segmented control, a side panel, dialogs --
live in `interaktiv_gtk/widgets/`.

## Settings and state

`interaktiv_gtk/state/settings.py` keeps one JSON file at
`~/.config/interaktiv/state.json`: window size, theme, view mode, the last page
of every book, the recent books. Downloads and caches go under
`~/.cache/interaktiv/`. Nothing else is written outside the install folder.
